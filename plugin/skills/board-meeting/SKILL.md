# 全體高管會議

CK 是社長。他召開這場會，是因為他沒有合夥人可以吵架。
**這場會議的價值來自意見不一致。如果六個部長講出來的東西大同小異，這場會就失敗了。**

## 執行流程

### 第一步：確認議題

如果 CK 給的議題夠明確，直接進行。
如果太模糊（例如「VoiceOut 接下來怎麼辦」），先用一句話把它收斂成一個可以表態的問題，講出來讓他確認，例如：
「我把議題定為：『下一季應該把全部力氣壓在單一校園的密度，還是先把商家端補起來？』這樣對嗎？」

### 第二步：平行召集六位部長

用 Agent 工具**同時**開六個 subagent（同一個訊息裡發出全部六個呼叫，不要一個一個等）。
每個 subagent 的 prompt 都是：

```
你是 VoiceOut 的 <職稱>。

先讀這兩個檔案，完全依照裡面的角色設定發言：
- <plugin根目錄>/context/voiceout-context.md
- <plugin根目錄>/skills/<角色>/SKILL.md

議題：<CK 的議題原文>
<如果有補充背景，附在這裡>

用繁體中文（台灣）回答，300 字以內。
只講你這個職位真正在意的東西 —— 不要試圖回答別人的問題。
要有明確立場。如果你反對這件事，就說反對。
```

六個角色分別是：`ceo`、`cfo`、`cto`、`cmo`、`coo`、`advisor`。

（`<plugin根目錄>` 用 `${CLAUDE_PLUGIN_ROOT}` 展開後的實際路徑。）

### 第三步：呈現會議記錄

按這個格式輸出，**先讓六個人講完，你才總結**：

```
## 📋 議題
<一句話>

---

### 👤 CEO
<原文>

### 💰 CFO
<原文>

### 🔧 CTO
<原文>

### 📢 CMO
<原文>

### ⚙️ COO
<原文>

### 🧠 首席顧問
<原文>
```

### 第四步：社長辦公室彙整

六段發言之後，加上這段。**這是整場會議最重要的部分，不要草率。**

```
---

## 🎯 給社長的彙整

**共識** —— 大家都同意的：
<條列。如果根本沒有共識，就誠實寫「這題沒有共識」>

**分歧** —— 意見打架的地方：
<誰對誰，爭點是什麼。這裡不要調和，要把衝突講清楚>

**最關鍵的一件事**：
<如果 CK 這週只能做一件事，是哪一件，為什麼>

**下一步（兩週內、花費最少）**：
<具體到他明天可以開始做>

**需要真實數據才能定案的**：
<列出六個 AI 都在用猜的部分 —— 提醒他這些答案只有真實使用者能給>
```

## 規則

- **不准把分歧磨平。** 分歧是 CK 花這個時間來換的東西。CFO 說不要花錢、CMO 說要投放，這種衝突要原樣呈現。
- **不准全體附和。** 如果六個部長都同意，在彙整裡明講：「六個人都同意，但這只代表推理一致，不代表市場同意。」
- 全程繁體中文（台灣）。
- 會議記錄不落地成檔案，除非 CK 要求。
